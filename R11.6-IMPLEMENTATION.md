# Synnical OS r11.6 implementation report

Build: `synnical-r22-synnical-os-r11-6-20260818`  
Version: `0.7.6`  
Base: r11.5 (`synnical-r22-synnical-os-r11-5-20260818`)

## What r11.6 changes

### SynnFlix / Continue Watching
- Server progress updates are monotonic: delayed player/ad events cannot rewind a newer timestamp or clear a completed state.
- Exact-title progress can be reset with `reset-progress`.
- Re-opening an already-completed movie or TV episode explicitly resets that selected item before playback so provider-side remembered state does not silently advance the user to another episode.
- Player messages are accepted only from the mounted player iframe and the Vidking origin family.
- A visible **Restart from beginning** control clears local + durable progress for the current item and reloads it from the start.
- Existing r11.4/r11.5 protections against player-remount loops are retained.

### Moderation
- Fixed Audit Logs `Maximum call stack size exceeded`: audit value rendering now handles primitives directly, bounds output, and detects circular objects instead of recursively calling itself forever.

### Games / cloud verification
- Removed resend storms and fresh-mailbox retry loops.
- A successful verification send starts a 65-second provider cooldown.
- Provider "too frequently / one minute" responses are converted to an explicit cooldown error.
- One verification email is sent, then the mailbox is polled longer instead of invalidating the code by requesting another one.

### Settings routing
- Opening a real Settings category or legacy section clears stale Settings search text first.
- A previous bad search such as `synnnical` can no longer cover every category with `No settings found` after navigation.

### Extensions removed
- Removed the Extensions panel and app registry entry.
- Removed extension API routes.
- Removed Sapphire runtime, service-worker router, browser content-script/plugin injection, extension tabs and toolbar UI.
- Removed `@x8r/sapphire` from package metadata.
- Removed the extension Prisma model from the target schema.
- Scramjet/Wisp browsing, tabs, workspaces, downloads and normal browser navigation remain.

### Synnical OS visuals
- Replaced the black taskbar treatment with layered liquid glass/acrylic, real backdrop blur, highlights and active glass tiles.
- Desktop and taskbar icons use a lighter high-contrast treatment with dark shadowing so they stay visible on pale wallpapers.
- Added persisted **Glass strength**.
- Added persisted wallpaper **Dim**, **Blur**, and **Saturation** controls.
- Wallpaper visual processing is isolated to the wallpaper layer instead of forcing those readability effects onto app windows.
- Added lock-screen **Hide sensitive text** for notification previews.

### Chat performance
- Message rows remain memoized and the full rendered message row tree is memoized away from composer keystrokes.
- Typing state emissions are throttled harder.
- Draft server persistence is debounced to 2 seconds and skipped when unchanged.
- Local message snapshot persistence is debounced to 1.8 seconds.
- Existing `content-visibility` optimization remains for message rows.

### Message counts
- Profile and account statistics derive message counts from actual non-deleted `Message` rows.
- Cached user counters are repaired when drift is detected.
- Feature-chat message creation increments the cached counter for future fast paths.

### Account security migration
- Forced one-time migration for already-signed-in users asks for **New password → Confirm → Security question/answer → recovery setup** and does not ask for the current password.
- That no-current-password setup route is blocked after `securitySetupCompletedAt` exists.
- Normal later password changes still require the current password.
- New registrations must provide a security question and answer and are marked security-setup complete at creation.
- Forgotten-password recovery remains a separate verified path requiring the security answer plus a one-time recovery code.

## 250-item OS feature backlog

r11.6 is built against the supplied 250-item OS backlog, while retaining the large set of OS features already present in r11.x: Start/All Apps, taskbar pin/reorder/auto-hide/alignment, tray overflow, Quick Settings, notifications/focus, widgets, workspaces/Task View, desktop icon sizing/grid, Files/Recycle Bin, snap layouts/groups, edge snapping, Aero Shake, keyboard snapping, Alt+Tab, clipboard history, emoji/symbol picker, touch keyboard, Night Light, lock screen, fullscreen, Start search, app restore and related account-backed settings.

This package does **not** mark every aspirational item as complete merely because it appeared in the backlog. Hardware/browser-restricted ideas and larger subsystems still need real implementations before they should be called finished. r11.6 prioritizes the reported breakages plus OS foundations that are real and testable.

## Deployment note for an existing database

The target Prisma schema removes the old extension metadata model. On an existing database, run normal `npx prisma db push` first and read Prisma's warning. If the only intended destructive change is dropping the obsolete extension metadata table, then use the repository's `npm run db:push:unsafe` after confirming that warning. Do not blindly accept unrelated data-loss warnings.
